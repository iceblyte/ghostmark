## 1. 背景与问题定义

### 1.1 问题来源

使用 Obsidian Web Clipper 从网页剪藏 markdown 笔记时，正文会带入大量**肉眼不可见或难以察觉**的垃圾字符。经查证（[obsidian-clipper #918](https://github.com/obsidianmd/obsidian-clipper/issues/918)），这类字符是**源网站注入的反爬水印**（例如某大型协作文档平台会在标题与正文中注入零宽字符簇），Clipper 原样搬运进 vault，并非 Clipper 自身的 bug。

实际受影响来源不止一家：多种协作文档平台、知识社区、个人博客等，**不同网站的水印技术各不相同**。这些字符在 Obsidian、Typora 及普通网页渲染中不显示任何图形，部分会在 IntelliJ IDEA 等代码编辑器中被标记，还有一些连 IDE 都不显示，只能靠方向键移动时察觉。

危害是实际的：

- 破坏搜索（含水印字符的词永远搜不到）；
- 破坏链接与双链（文件名/标题被污染时链接建立失败）；
- 破坏 diff 与 git 历史（整行看似未改实则已变）；
- 复制进代码/终端时毁掉程序（词内水印：`pyt⟪2062⟫hon`、`Power⟪061C⟫⟪061C⟫Point`）。

> 记号约定：`⟪XXXX⟫` 表示此处存在一个 U+XXXX 不可见字符。本文档自身不嵌入任何真实不可见字符。

### 1.2 真实样本解剖（脱敏后）

**样本 A**：一篇 14,426 字符的中文技术笔记，剪自站点 A（中文知识付费社区，付费内容）。全文共 **801 个不可见水印字符 + 48 处 base64 追踪 token**，三种水印技术叠加：

| # | 技术 | 字符/形态 | 数量 | 分布特征 |
|---|---|---|---|---|
| 1 | 词内隐形字符簇 | U+2062 INVISIBLE TIMES ×108；U+061C ARABIC LETTER MARK ×216 | 324 | 以 2~3 个一簇插进**单词内部**：`pyt⟪2062⟫⟪2062⟫hon`、`Hel⟪061C⟫⟪061C⟫lo`、`functi⟪2062⟫⟪2062⟫on` |
| 2 | 行尾空宽空格指纹串 | U+2002 EN SPACE ×300；U+2009 THIN SPACE ×177 | 477 | 每段结尾一个固定重复的 32 字符混合串（两种空格宽度交替排列，疑似二进制编码水印） |
| 3 | 正文内嵌追踪 token | 44 字符 base64 串（形态 `[A-Za-z0-9+/]{43}=`） | 48 处，仅 **10 个不同值** | 直接粘在段落文字后面，是**可见**垃圾；重复率极高（指纹特征） |

关键事实：

- 经典的 U+200B ZWSP 在样本 A 中**一个都没有**——真实数据比"教科书式零宽字符清单"怪得多。策略必须从真实数据长出来，按 Unicode 表格兜底。
- U+2002/U+2009 是**可见宽度**的空格（Zs 类），不属于零宽字符——问题域比"零宽字符"更宽，应称为"不可见/可疑字符"。
- 样本 A 的 11 个围栏代码块**未被污染**；但策略上代码块仍应参与清理——无语义不可见字符在代码中只可能是污染（复制即毁代码），清理是零风险的防御性设计。
- 样本 A 剪自付费内容：其水印模式完整固化进合成 fixture 后，真实文件已删除、不再留存。

### 1.3 现有方案调研与不足

| 方案 | 结论 |
|---|---|
| Web Clipper 模板过滤器（源头预防） | 有 `replace` 过滤器，但存在未修复 bug [#916](https://github.com/obsidianmd/obsidian-clipper/issues/916)：`\s` 匹配字面 "s"、`\p{…}` Unicode 属性类不可用，只能用字面字符类硬凑。**预防只能算部分可行，插件端清理仍是主防线** |
| Clipper 官方管线 | 提取依赖 Defuddle 曾把波斯语合法的 ZWNJ 整体删除、毁掉复合词（[#625](https://github.com/obsidianmd/obsidian-clipper/issues/625)，经上游 [kepano/defuddle#103](https://github.com/kepano/defuddle/pull/103) 修复）——**"程序一刀切会误删正确内容"有官方前科**，这是本插件做上下文分类而非静态白名单的最强论据 |
| [gremlins](https://github.com/xryul/gremlins)（社区插件） | 成熟。CM6 装饰在 Source/Live Preview 可视化 + 逐行点击修复 + "Fix all in current note" + 单步撤销。**不足**：字符表缺 U+2061~2064 与 U+061C（恰是本场景主力）；对 ZWNJ/LRM/RLM 无条件删除（会重蹈 #625）；仅当前笔记，无批量、无剪藏触发、无上下文分类 |
| [markdown-fixer](https://github.com/muhammedhunaid/markdown-fixer)（社区插件） | 粘贴时自动清理 + 手动命令。极不成熟（0 star、8 commits）、无预览、无排除项、无可视化 |

> 澄清（v1.1）：本插件默认清除 U+200E/U+200F（LRM/RLM），与上表对 gremlins 的批评并不矛盾——#625 教训的实质是 **ZWNJ 承载构词语义，必须默认保护**（本插件已如此，见策略表"黄类"）；而本产品内容画像（§2）明确无 RTL 语言，LRM/RLM 在非 RTL 文本中出现即视为污染，且两码点均可在设置中逐码点改为保留，保留了 gremlins 所缺失的用户控制。

### 1.4 差异化定位

Ghostmark 相对现有方案的五个差异点：

1. **完整码点覆盖**——补齐 gremlins 缺失的 U+2061~2064、U+061C，及本场景实际出现的空格宽度水印；
2. **上下文感知分类**——区分水印簇、语义字符（emoji ZWJ、ZWNJ）、空格类，而非静态白名单一刀切；
3. **两级清除带确认与撤销**——清除全部 / 清除选区，执行前确认、执行后单步可撤销；
4. **拾取码点机制**——光标处一键把未知字符加入清理名单，应对新网站的未知水印；
5. **演进路线**——vault 批量、剪藏自动处理、垃圾模式规则库（正则 + 重复指纹）。

技术可行性：CM6 装饰在 Obsidian 双编辑模式下的可视化已由 gremlins 背书；`Plugin.registerEditorExtension`、`Vault.on('create')`、`Vault.process`、状态栏 API 均为公开稳定 API，无技术风险项。

## 2. 用户与内容画像

- 中文笔记为主，剪藏来源多样（协作文档平台、知识社区、个人博客等）。
- 内容画像：**有数学公式和 emoji，无 RTL 语言**（阿拉伯语/希伯来语/波斯语）。
- vault 在 git 管理下，可作最终安全网。
- 界面语言：英文 / 简体中文可切换（FR-12），默认跟随 Obsidian 界面语言。
- 产品标准："自用但随时可发布"——按社区插件上架标准实现，先自用，顺手再上架。

## 3. 功能需求（v1）

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-1 | **检查模式** | 一个可开关的编辑器模式（对标编辑/阅读切换的心智模型）：开启后，笔记中所有命中字符以行内字形 widget 呈现；Source 与 Live Preview 双模式可用 |
| FR-2 | **分类可视化** | 三色体系：红=无语义不可见字符（垃圾），蓝=空格类，黄=受保护语义字符（默认清除名单之外，标记以提示"它存在但默认不动"） |
| FR-3 | **标记密度** | 紧凑（每类一个符号，如 `⌷`、`␣`）与详细（显示码点缩写如 `2062`）两档，默认紧凑 |
| FR-4 | **悬停详情** | hover 显示：字符名称、码点、类别、建议动作 |
| FR-5 | **行号槽徽标** | 有命中的行在 gutter 显示计数徽标 |
| FR-6 | **状态栏** | 常驻显示当前笔记命中总数（如 `Ghost: 47`），点击切换检查模式。仅桌面（移动端无状态栏 API，入口为命令面板，见 NFR-6） |
| FR-7 | **清除全部** | 对当前笔记按策略表执行清理；执行前 Modal 确认（分类计数汇总）；执行后单步可撤销 |
| FR-8 | **清除选区** | 仅对选中文本执行清理（base64 token 这类可见垃圾靠它手动删） |
| FR-9 | **拾取码点** | 光标停在任意字符上执行命令 → 弹窗展示码点信息 → 确认后**按类别写入建议动作**（无语义不可见→清除；空格类→转普通空格；语义类→保留）加入策略表，持久化保存。应对新网站的未知水印 |
| FR-10 | **命令入口** | 四个命令均进命令面板并配建议快捷键：清除全部 / 清除选区 / 切换检查模式 / 拾取码点 |
| FR-11 | **设置界面** | 三组：字符策略表（默认表逐码点动作 + 拾取追加区）、上下文规则（数学块 / ZWNJ / 代码块空格）、界面（密度、清除前确认、状态栏、检查模式记忆） |
| FR-12 | **界面语言** | 英文 / 简体中文可切换，默认跟随 Obsidian 界面语言；覆盖全部 UI 文案（hover、Modal、设置、Notice），文案集中管理 |

## 4. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-1 | **不误删**：上下文分类器保证 emoji ZWJ 序列逐字节保留；ZWNJ/变体选择符默认保留；数学块默认只标记不清除；执行前确认 + 单步撤销 + git 三层兜底 |
| NFR-2 | **去得干净**：默认策略表覆盖本场景全部已知水印码点；拾取码点兜底未知字符 |
| NFR-3 | **性能**：万字符级笔记检查模式无明显卡顿 |
| NFR-4 | **可发布**：manifest 完整、无外部网络请求、构建可复现、设置界面结构清晰 |
| NFR-5 | **可测试**：分类/扫描/清理逻辑为纯函数模块，与 Obsidian API 解耦，单元测试全覆盖 |
| NFR-6 | **平台**：`isDesktopOnly: false`；检查模式与命令在移动端可用，状态栏仅桌面（移动端以命令面板为唯一入口） |

## 5. 明确不做（Non-goals）

- **真·第四编辑模式**（在编辑/阅读旁加按钮）：无公开 API，需 patch Obsidian 内部，随版本更新易碎、上架有风险。以"检查模式开关"达成同等体验。
- **自动改写有语义的字符**：ZWJ 永久保护，写死不设开关。
- **v1 不做**：vault 批量、剪藏自动处理、正则规则库（见 §7 路线图）。
- **v1 不内置站点专属规则**（如 base64 token 正则）：容易误伤笔记里合法的 base64 内容，交给 v2 规则库 + v1 的选区清除。
- **界面语言只做英文与简体中文**：不做更多语言与通用 i18n 框架；文案集中管理，为后续扩展预留结构。

## 6. 验收标准

1. 合成 fixture（`fixtures/watermark-fixture.md`）检测计数与三色分桶精确，断言到每个码点：U+2062 ×108、U+061C ×216、U+2002 ×300、U+2009 ×177（不可见字符合计 801，与样本 A 持平）、base64 token 48 处 / 10 个不同值；
2. 清除全部后零残留（保护对象除外）；
3. emoji ZWJ 序列逐字节不变；
4. 数学块默认未被修改（设置开关打开后才清理）；
5. 代码块内空格类变成普通空格、无字符丢失；
6. **界面手动验收**：三色标记、紧凑/详细两档密度、hover 详情、行号槽徽标、状态栏计数与点击切换逐项符合 §3 描述；移动端检查模式可用（状态栏除外）；
7. **语言切换**：界面语言设为英文 / 中文后，hover、Modal、设置、Notice 文案全部跟随切换，无硬编码遗漏（en/zh 键集合一致性由单测兜底）。

## 7. 路线图

| 阶段 | 内容 |
|---|---|
| **v1** | 本文档全部需求 |
| **v1.5** | vault 批量扫描报告 + 选择性清理（git 兜底）；文件名 / frontmatter 标题清洗（文件名水印是 [#918](https://github.com/obsidianmd/obsidian-clipper/issues/918) 的实锤场景，但文件重命名超出编辑器内操作范围） |
| **v2** | 剪藏落盘自动处理（`Vault.on('create')`，默认关、可配目录）；独立审计视图（全篇总览）；垃圾模式规则库（自定义正则如 `[A-Za-z0-9+/]{43}=?` + 重复指纹启发式——样本 A 中 base64 token 48 处仅 10 个不同值，重复率即指纹） |
